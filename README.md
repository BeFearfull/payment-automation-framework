# Payment Automation Framework

QA automation foundation for an e-commerce payment journey using **Razorpay Test Mode**, Flask, Playwright, and Pytest.

## Stack

- Python + Flask
- Razorpay Python SDK (orders, signature verification, payment/order fetch)
- Razorpay Standard Checkout (frontend)
- Playwright / Pytest / pytest-html

**Tested locally with:** Python **3.14.4** (Windows 11). Other versions are untested in this project.

## Fresh setup on a Windows laptop

Do **not** copy a `venv/` folder between machines. Always create a new virtual environment on the target PC.

```powershell
# From the repository root (example: D:\Payment Automation)
python --version
python -m venv venv

# PowerShell activation (if blocked, run once for the current user):
# Set-ExecutionPolicy -Scope CurrentUser RemoteSigned
.\venv\Scripts\Activate.ps1

python -m pip install --upgrade pip
pip install -r requirements.txt
python -m playwright install chromium

copy .env.example .env
if u want to use the protected .env.age file
use - age -d -o .env .env.age
then enter the provided passphrase
# Edit .env and set Razorpay Test Mode keys (rzp_test_* only).
```


### `.env` configuration

Use `.env.example` as the template. Required:

- `RAZORPAY_KEY_ID` — must start with `rzp_test_`
- `RAZORPAY_KEY_SECRET` — Test Mode secret (never commit `.env`)
- `FLASK_SECRET_KEY` — change from the demo default for shared environments
- Optional: `RAZORPAY_TEST_OTP` (default `1234`), `RAZORPAY_TEST_OTP_FAIL` (short OTP `<4` digits, default `12`)

**Capture configuration:** `/payment-success` unlocks only when Razorpay reports payment status **`captured`**. In the Razorpay Test Mode dashboard, enable **automatic capture** (or capture payments) so end-to-end OTP success (AUTH-01) can pass. An `authorized` payment alone does **not** unlock success.

```powershell

```

Open `http://127.0.0.1:5000`.

## Payment flow

1. Homepage shows **Wireless Headphones** at ₹1,499.
2. Add to cart → **Proceed to Payment**.
3. Browser calls `POST /create-order` (server creates a Razorpay Test Mode order).
4. Frontend opens Razorpay Standard Checkout with `order_id` + public `key_id` only.
5. On Checkout success, frontend posts fields to `POST /verify-payment`.
6. Backend verifies the HMAC signature.
7. Backend fetches the payment and order from Razorpay and requires **`captured`** status with matching order id, amount, and currency (browser values are not trusted).
8. Only then is `GET /payment-success` allowed.
9. Failures / dismissals route to `GET /payment-failure`.

Card numbers, CVV, and OTP are never stored by this application.

## Important routes

| Method | Path | Purpose |
|--------|------|---------|
| GET | `/` | Shopping homepage |
| POST | `/create-order` | Create Razorpay test order |
| POST | `/verify-payment` | Signature + lifecycle verification |
| GET | `/payment-success` | Success page (verified + captured only) |
| GET | `/payment-failure` | Failure page |

## Security notes

- Secret key stays on the server (`.env`). Never commit `.env`.
- Frontend receives only the public key ID.
- Frontend success callback alone is never trusted.
- Do not copy `venv/` between laptops.

## Web automation

Page objects live under `tests/pages/`. Markers:

- `@pytest.mark.web` — homepage/cart/checkout UI
- `@pytest.mark.payment` — verification gate / order API
- `@pytest.mark.unit` — mocked (not live Razorpay transactions)
- `@pytest.mark.otp` — Test Mode mock OTP E2E
- `@pytest.mark.security` — session/secret/forgery checks

QE docs: [test coverage matrix](docs/test-coverage-matrix.md) · [QE audit](docs/qe-audit-report.md) · [cleanup audit](docs/repository_cleanup_audit.md)

```powershell
.\venv\Scripts\Activate.ps1

# WEB + payment suite
python -m pytest tests -m "web or payment" --html=reports/web_payment_report.html --self-contained-html --browser chromium

# Security suite
python -m pytest tests -m security --html=reports/security_phase2_report.html --self-contained-html --browser chromium

# Test Mode mock OTP suite (headed recommended)
python -m pytest tests -m otp --headed --html=reports/otp_report.html --self-contained-html --browser chromium

# Full regression
python -m pytest tests --headed --html=reports/full_regression_phase2_report.html --self-contained-html --browser chromium
```

`artifacts/` and `reports/` are gitignored and regenerated by local runs.

**OTP notes:** AUTH-01/AUTH-02 automate Razorpay **Test Mode mock OTP** only (not live bank SMS). Prefer `--headed`. If a visible hCaptcha appears, tests skip rather than bypass it.

**AUTH-02 failure OTP:** Use a short OTP (`<4` digits, default `12`). In the Checkout iframe mock ACS, the often-cited `12345` value **succeeds** and must not be used for the negative test.
